# 지원 기능

이 부록은 cuda-oxide의 기능표입니다. 컴파일러 기능, 런타임 API, 하드웨어 기능과 현재 지원 상태를 정리했습니다. 내용은 컴파일러·런타임 소스와 테스트에서 가져왔습니다.

**범례:** **완전**은 테스트를 통과하고 동작함, **부분**은 알려진 제한이 있지만 제공되고 동작함, **계획**은 로드맵에 있음, **해당 없음**은 적용할 수 없거나 필요성이 확인되지 않음을 뜻합니다.

## 컴파일러: 메모리 모델

| 기능 | 상태 | 설명 |
|:--|:--|:--|
| HMM / 통합 메모리 관리 | **완전** | `cudaMemcpy` 없이 GPU가 호스트 메모리를 읽고 씁니다. 클로저에서 참조를 캡처하면 HMM으로 호스트 포인터에 접근합니다. Turing 이상 GPU, Linux 6.1.24 이상, CUDA 12.2 이상이 필요합니다. |
| 통합 구조체 ABI (`#[repr(C)]` 불필요) | **완전** | 디바이스 구조체 레이아웃이 호스트와 일치합니다. 컴파일러가 rustc의 실제 레이아웃을 조회하고 LLVM IR에 패딩을 명시합니다. 기본 `#[repr(Rust)]`에서도 동작합니다. |
| 동적 레이아웃 일치 | **완전** | rustc의 `fields_by_offset_order()`와 바이트 오프셋을 조회해 올바른 필드 순서와 패딩을 갖는 LLVM 구조체를 만듭니다. LLVM 데이터 레이아웃에 의존하지 않습니다. |
| 패킹 레이아웃 (`#[repr(packed)]`) | **부분** | `addr_of!((*p).field)`로 포인터를 통해 필드 주소를 만들면 rustc의 정확한 오프셋을 사용하므로 `read_unaligned`/`write_unaligned` 왕복이 `packed(N)`을 포함해 동작합니다. 값으로 생성·로드·저장하는 경우와 `[Packed; N]` 요소 주소 계산도 바이트 단위로 일치하는 패킹 LLVM 저장소를 사용할 수 있습니다. 중첩 승격 가능한 상수 배열은 자연 또는 패킹 표현이 필드 오프셋과 저장 크기를 정확히 재현할 때 불변 디바이스 전역 경로를 사용합니다. 겹치거나 표현할 수 없는 레이아웃은 거부합니다. |
| 포인터 거리 (`offset_from`) | **완전** | `ptr_offset_from` / `ptr_offset_from_unsigned` 인트린식과 `offset_from`, `offset_from_unsigned`, `byte_offset_from`, `byte_offset_from_unsigned` 메서드는 주소 차이를 rustc가 보고한 대상 크기로 나눕니다. 결과는 부호 있는 `isize` 또는 부호 없는 `usize`입니다. 크기 0 타입의 대상은 오류입니다. |
| 휘발성 읽기/쓰기 | **완전** | `core::ptr::read_volatile` / `write_volatile`의 휘발성 속성이 MIR 가져오기부터 mem2reg, MIR-LLVM 변환, 텍스트 출력까지 유지됩니다. volatile 접근은 승격하지 않으며 PTX에 `ld.volatile` / `st.volatile`을 생성합니다. |
| 대량 복사 (`copy_nonoverlapping`) | **완전** | `core::ptr::copy_nonoverlapping`은 `mir.memcpy`를 거쳐 `llvm.memcpy`로 변환됩니다. 요소 수는 대상 타입 크기에 따라 바이트로 환산하며, 인트린식 오버로드는 주소 공간과 길이 너비를 반영합니다. |

## 컴파일러: 타입 시스템

| 기능 | 상태 | 설명 |
|:--|:--|:--|
| 제네릭 및 단형화 | **완전** | 트레이트 경계가 있는 제네릭 커널과 디바이스 함수, rustc MIR에서 수집한 단형화 인스턴스, const 제네릭을 지원합니다. |
| 열거형 (`Option<T>`, `Result<T,E>`, 사용자 정의) | **완전** | 판별값 추출과 페이로드 접근을 포함합니다. 패턴 매칭도 동작합니다. |
| 구조체 생성 및 필드 접근 | **완전** | 구조체 리터럴, 필드 접근, 값 전달과 반환을 지원합니다. 사용자 정의 구조체에 별도 어노테이션이 필요하지 않습니다. |
| 배열 (`[T; N]`) | **완전** | 정적 생성과 상수·런타임 인덱스 접근을 지원합니다. 기본 및 중첩 배열 상수를 생성하며 가변 배열은 메모리 기반 표현으로 자동 승격됩니다. |
| `CuSimd<T, N>` SIMD 타입 | **완전** | `x`/`y`/`z`/`w` 접근자, 런타임 및 컴파일 타임 인덱싱, `to_array` 변환을 제공하는 제네릭 SIMD 레지스터 타입입니다. |
| ABI 스칼라화 | **완전** | 커널 경계에서 슬라이스를 `(ptr, len)`으로 분해하고 함수 안에서 복원합니다. 구조체와 클로저는 단일 byval `.param`으로 전달되며, 디바이스 함수 호출 내부에서는 필드 평탄화가 계속 적용됩니다. |
| grid-constant 매개변수 | **완전** | `#[grid_constant] value: &T`는 `T`를 값으로 전달하면서 그리드 전체 읽기 전용 주소를 유지합니다. 호스트 실행은 unsafe입니다. 크기가 0이 아닌 내부 가변성이 없는 타입, 실행 범위 참조, Volta 이상 대상이 필요합니다. |

배열 상수는 정수, `f16`, `f32`, `f64` 같은 기본 원소와 중첩 배열을 지원합니다. 지원되는 스칼라·열거형·튜플·크기 0 필드로 재귀적으로 구성된 튜플도 포함됩니다. 튜플의 요소 간격과 필드 오프셋은 내부 및 끝 패딩을 포함한 rustc 레이아웃을 따릅니다. 튜플 값 상수도 같은 레이아웃 인식 디코더를 사용합니다. 직접 구조체 상수와 참조를 통한 승격 상수 역시 각 필드를 rustc 오프셋에서 읽습니다. 따라서 패딩, 필드 재배치, `#[repr(C)]`, 중첩 구조가 올바르게 디코딩되고, 패딩 구조체 배열의 요소 간격도 저장 크기를 기준으로 합니다.

포인터가 없는 초기화된 union 상수는 활성 필드를 추측하지 않고 rustc가 평가한 저장 이미지를 사용합니다. 초기화된 바이트는 보존하고 비활성 필드의 초기화되지 않은 바이트는 `undef`로 둔 뒤 레이아웃이 일치하는 union 타입으로 변환합니다. 직접 union, 튜플·구조체 안의 union, 런타임 인덱스 `[U; N]`, `MaybeUninit<T>` 상수를 포함합니다. 재귀적으로 승격 가능한 구조체 배열은 읽기 전용 테이블을 스레드별 로컬 메모리로 복사하지 않도록 불변 디바이스 전역 메모리 경로를 사용합니다. 지원되는 얇은 포인터와 참조도 포함하며, 평가된 바이트 이미지와 심볼형 디바이스 전역 재배치를 보존합니다. 재배치 대상과 바이트 덧셈값을 명시적으로 기록하고, 중복 제거 시 타입·바이트뿐 아니라 재배치 정체성도 비교합니다.

`const R: &[Struct; N] = &TABLE` 형태의 배열 포인터 상수도 모든 요소가 승격 가능하고 변환된 저장 크기가 rustc 레이아웃과 일치하면 같은 불변 전역 메모리를 사용합니다. 바깥 포인터가 할당의 일부 범위를 가리키면 그 범위 안의 재배치 원본 오프셋을 승격된 초기화 데이터에 맞춰 다시 계산하면서 대상과 덧셈값을 유지합니다. 지원되지 않는 기본 배열 상수는 가능한 경우 기존 요소별 경로를 사용하지만, 정확한 대체 경로가 없는 배열 포인터 상수는 안전하게 실패합니다. `repr(align(N))` 크기 0 타입처럼 크기는 0이지만 정렬이 강한 필드는 기존 정렬 인식 값 경로를 사용합니다. `repr(packed)`와 `repr(packed(N))`도 rustc 오프셋을 정확히 재현할 수 있을 때 승격 대상이며 값·참조 형태는 같은 불변 초기화 데이터로 중복 제거됩니다.

불변 테이블 승격 경로를 사용하지 않는 배열·튜플·구조체 **상수**의 얇은 포인터 필드는 필드마다 `MirGlobalAllocOp`으로 생성되며 정적 메모리 안의 바이트 덧셈값도 보존합니다. `array_constants` 회귀 테스트는 정적 참조와 정적 하위 객체를 가리키는 포인터 테이블을 포함해 최적화된 코드에 스레드별 테이블 복사본이 남지 않는지 확인합니다. 집합 상수의 슬라이스 fat pointer도 데이터 포인터가 디바이스 정적 메모리를 가리키고 같은 원소 타입의 배열-슬라이스 뷰이면 지원합니다. `usize` 길이 메타데이터는 독립적으로 디코딩하며 중첩 필드 오프셋과 포인터 덧셈값도 보존합니다.

포인터만 포함된 union은 자리표시자 바이트를 변환하는 대신 타입이 지정된 포인터 전달체 하나를 재구성해 재배치 출처를 유지합니다. 호환되는 `SharedRef` 대안은 변환 후 대상 타입이 같아야 하며 `UniqueRef` union 상수는 거부합니다. 원시 포인터 대안은 포인터 종류, 가변성, 주소 공간이 같고 대상 뷰만 달라도 됩니다. 재배치가 없고 저장소가 완전히 초기화된 자연 정렬 포인터 한 워드이며, 대안이 한 종류의 일반 원시 포인터와 전체 너비 정수로 구성된 포인터/정수 union은 예외적으로 rustc 평가 바이트 이미지를 사용할 수 있습니다. 이때 이미지는 정수 필드에만 변환하고 union에 넣어 비활성 포인터를 생성하지 않습니다.

재배치가 있는 포인터/정수 union, union 안의 fat 또는 중첩 포인터 저장소, 과도한 정렬·패딩을 가진 포인터 union, 지원하지 않는 fat-pointer 메타데이터, 포인터 대 배열 union 상수(`&[U; N]`)는 거부합니다. 최상위 얇은 포인터 전용 디바이스 전역 union 초기화는 0번 바이트의 단일 전체 너비 재배치를 보존할 수 있지만, 포인터와 정수가 섞인 초기화는 지원하지 않습니다.

union 필드가 공유 메모리 포인터를 직접 또는 구조체·길이가 제한된 배열을 통해 보유하면 generic 포인터 저장소를 사용합니다. 이 저장소의 바이트 이미지는 모든 대상에서 같고 정수 뷰는 `ptr as usize`와 같습니다. 공유 메모리 창 안의 오프셋이 필요하면 `cvta_generic_to_shared_offset` 또는 `cvta_generic_to_shared_u32`를 사용하세요. 고정 배열을 펼친 결과 공유 메모리 포인터가 16개를 넘으면 거부합니다. 구조체 안에 직접 넣은 포인터는 이 한도에 포함되지 않습니다. `u.ptr = p`, `&u.ptr`, `&mut u.ptr`처럼 해당 필드의 제자리 주소를 취하는 방법은 진단과 함께 거부됩니다. union을 값으로 만든 뒤 필드를 값으로 읽으세요.

타입이 지정된 공유 포인터 `SharedPtr<T>`도 같은 제한을 따릅니다. union이나 `MaybeUninit<SharedPtr<T>>`는 union 저장 규칙에 따라 거부됩니다. 이를 담는 `repr(packed)` 구조체는 위 패킹 전달체 제한을 따릅니다. 이를 단독 또는 구조체·배열 안에 담은 커널 매개변수는 허용되지 않으며, libNVVM 경로에서 더 좁은 필드와 함께 담은 구조체는 배열이나 공유 메모리에서 아직 지원하지 않습니다.

열거형 상수는 디바이스 정적 메모리로 향하는 페이로드 재배치를 바이트 덧셈값과 함께 보존합니다. niche 인코딩 `Option<&T>`와 직접 태그가 붙은 레이아웃, 얇은 참조 및 튜플·구조체·배열 페이로드 안의 포인터가 포함됩니다. 재배치가 포함된 열거형 상수는 튜플, 구조체, 배열 상수 안에 중첩할 수 있습니다. 익명 승격 할당은 지원하지 않습니다.

## 컴파일러: 클로저

| 기능 | 상태 | 설명 |
|:--|:--|:--|
| 값 캡처 클로저 (`FnOnce`) | **완전** | 클로저 구조체 전체를 하나의 byval 커널 인자로 전달합니다. `move |x| x * factor` 패턴을 지원합니다. |
| 참조 캡처 클로저 (`Fn`/`FnMut`) | **완전** | 호스트 포인터를 포함한 클로저 구조체를 단일 byval 인자로 전달하고 HMM을 통해 GPU에서 포인터를 읽습니다. |
| 호스트-디바이스 클로저 | **완전** | 호스트에서 정의해 제네릭 커널에 전달합니다. 계수를 캡처하는 다항식 계산을 테스트했습니다. |
| 디바이스 내부 클로저 | **완전** | 디바이스에서 만들고 사용하며 디바이스 함수에 전달하는 경우를 지원합니다. |

## 컴파일러: 제어 흐름

| 기능 | 상태 | 설명 |
|:--|:--|:--|
| 정수 `match` | **완전** | 정수 다중 분기를 조건 분기 체인으로 생성합니다. |
| 열거형 `match` | **완전** | `Option<T>` 및 사용자 정의 열거형의 판별값과 페이로드 접근을 지원합니다. |
| 범위·반복자·enumerate `for` 루프 | **완전** | 범위, `slice.iter()`, `enumerate()`, 중첩 루프, `break`, `continue`의 반복자 디슈거링을 지원합니다. |
| `while` 루프 / `if-else` | **완전** | 기본 제어 흐름을 지원합니다. |
| `break` 및 `continue` | **완전** | 조기 종료를 포함해 for/while 루프에서 사용할 수 있습니다. |
| 루프 언롤 어노테이션 | **부분** | `#[unroll]`, `#[unroll(N)]`은 명시적으로 카운트하는 `while`과 정수 카운터 범위 `for`(`a..b`, `(a..b).rev()`, `isize` 포함)를 처리합니다. `a..=b`, `.step_by(k)` 같은 다른 반복자 루프는 아직 인식하지 않습니다. 중첩 루프와 여러 `continue` 경로를 지원합니다. 전체 언롤링은 `break`와 여러 종료 지점을 보존하며 부분 언롤링은 양의 간격, 불변 상한, 일반 헤더 종료가 있는 `<`/`<=` 루프만 지원합니다. 복사본 1,024개, 복제 블록 8,192개, 복제 연산 65,536개로 제한됩니다. |
| 단형화 후 죽은 분기 | **부분** | 제네릭 특수화 후 죽는 분기(예: `if M::ENABLED`의 상수 거짓 경로)는 심볼 수집, 패닉 검사, 포인터 주소 공간 추론에서 제외됩니다. rustc가 직접 상수 접는 switch만 가지치기하므로 여러 단계의 상수 복사 체인은 양쪽 경로를 유지합니다. 이는 일반 상수 전파가 아닙니다. |

| `gpu_assert!` | **완전** | 메시지 없는 형식은 실패 시 `trap()`을 호출합니다. 문자열 메시지 형식은 CUDA 디바이스 `__assertfail`을 호출해 메시지·호출 위치를 보고하고 `CUDA_ERROR_ASSERT`를 반환합니다. |

## 아직 구현되지 않음

| 기능 | 상태 | 설명 |
|:--|:--|:--|
| Rust `asm!` 매크로 | **계획** | CUDA 인라인 PTX에는 `ptx_asm!`을 사용하세요. Rust MIR `InlineAsm` 직접 변환은 구현되지 않았습니다. |
| 동적 디스패치 (`dyn Trait`) | **해당 없음** | 정적 디스패치 제네릭을 사용하세요. 현재 실제 필요성이 확인되지 않았습니다. |
| 힙 할당 (`Box`, `Vec`) | **해당 없음** | CUDA에는 커널 내부 디바이스 힙(`malloc`/`free`)이 있고 컴파일러가 `alloc` 크레이트를 허용하지만, 디바이스 `#[global_allocator]`는 연결되어 있지 않습니다. 디바이스 `malloc`은 직렬화·단편화·비병합 접근으로 매우 느립니다. 슬라이스와 `SharedArray`를 사용하세요. |
| `String` / `format_args!` | **해당 없음** | 형식화된 출력에는 `gpu_printf!`를 사용하세요. |
| 패닉 / 스택 되감기 | **해당 없음** | MIR의 패닉 경로는 있지만 컴파일러가 `core::panicking::*`와 되감기 간선을 제거합니다. GPU 하드웨어는 Volta 이후 스레드별 호출 스택으로 되감기를 지원할 수 있지만 CUDA 도구(nvcc/ptxas)가 아직 노출하지 않아 PTX에 landing pad가 남지 않습니다. 런타임에 패닉 경로에 도달하면 `panic=abort`와 마찬가지로 GPU 트랩이 발생합니다. NVIDIA는 자동차 안전용 CUDA C++ 예외 지원을 개발 중이며 현재 설계는 이를 수용할 수 있습니다. 현재 명시적 런타임 검사는 `gpu_assert!()`와 `trap()`을 사용하세요. 정상 본문을 가진 `-> !` 함수는 일반 호출되며 뒤에 `unreachable`이 붙습니다. 패닉 진입점, 패닉만 수행하는 `-> !` 본문, 함수 포인터 호출만 트랩으로 변환됩니다. |
| 표준 라이브러리 (`std`/`alloc`) | **해당 없음** | `std`는 금지됩니다. 수집기는 `alloc`을 허용하지만 할당기가 없습니다. `core`만 완전히 동작하며 `Option`, `Result`, 반복자는 사용할 수 있습니다. |
| 텍스처 메모리 | **해당 없음** | Hopper 이상에서 TMA를 사용할 수 있어 우선순위가 낮습니다. |
